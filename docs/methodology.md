# DMAIC Methodology

## Define
Prepare a project charter, business case, problem statement, measurable goal, scope, stakeholders, CTQs and SIPOC. Agree an operational definition of a defect.

## Measure
Document data collection, units, sampling frequency, measurement-system adequacy, calibration, missingness, duplicates and baseline defect rate. Cp/Cpk require valid specification limits and a stable process.

## Analyze
Use Pareto, stratification by line/shift/machine/material, distributions, time trends and correlations. Use t-tests, ANOVA or chi-square only when assumptions and sampling design are appropriate. Predictive feature importance is not causal proof.

## Improve
Translate verified root causes into countermeasures. Prioritize impact, feasibility, cost and risk. Pilot approved changes and evaluate before/after outcomes using a suitable design. Do not claim savings before verification.

## Control
Define CTQ, metric, owner, sampling frequency, control chart, standard work, audit cadence and reaction plan. Control limits are not specification limits.

## Machine learning
Random Forest predicts binary defect risk. Preprocessing is fitted inside the pipeline. Report prevalence, precision, recall, F1, ROC-AUC, confusion matrix and threshold rationale. Use time/group validation when the deployment question requires it.

## Data disclaimer
The bundled data is synthetic, not Toyota production data. Company-specific conclusions require authorized data and independent validation.
